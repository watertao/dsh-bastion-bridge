# 固定链路部署拓扑（中继 + nginx 转发部署）

这是「本工作区」形态的访问链路，与技能正文描述的直连部署不同。遇到行为差异时以本文为准。
真实地址清单（笔记本 IP、中继 IP、目标机 IP、Windows 用户名）见同目录
`deployment-local.md`——**本地文件，不入公开仓库**；它不存在时按本文占位符向用户询问。

## 链路

```
Mac（AI 会话）
  --HTTP--> <笔记本IP>:9766  办公笔记本（Windows）上的 nginx
              └--转发--> 127.0.0.1:8766  齐治桥接器（putty.exe 替身，单实例）
                           └--SSH--> 齐治中继节点 <中继IP>
                                        （一次性账号 + 控制台一次性凭据，命令行主机是中继 IP）
                                        └--login:/password: 二段登录--> 目标机
                                             （如 root@<目标IP>，凭据来自 relay_hosts）
```

## 事实清单

- **Mac 侧端口文件 `~/.sshbridge/qizhisshbridge/active_port.txt` 固定是 `<笔记本IP>:9766`**（nginx
  地址），不随目标机变化；桥接器每次都绑 8766，无需追端口。
- **桥接器真身跑在办公笔记本上**。config.json、bridge.log、active_port.txt 的真身都在笔记本的
  `%LOCALAPPDATA%\sshbridge\QizhiSSHBridge\`——Mac 上的同名文件/目录不是事实来源，
  诊断时让用户看笔记本上的 `logs\bridge.log`。
- **齐治控制台传给 putty 的主机是中继节点 IP，不是目标机**。目标机地址只出现在
  二段登录提示符文本里（`root@<目标IP>'s password:`）。因此：
  - 目标机凭据按桥接器 config.json 的 `relay_hosts` 配置，**键 = 目标机 IP**；
    桥接器（v1.8.0 修复版起）在应答 password: 提示符时解析出目标主机后查表，未命中回落 `"*"` 再回落
    全局 `relay_password`。
  - 老版本（按命令行主机查表）在中继部署下条目永不命中，会把全局密码发给所有目标机——表现为
    某台机器固定 `Permission denied`，而原版 putty 手输能上。
- **launch_mode=auto，单实例文件锁**：桥接器已在跑时，再点击资源会转交原版 putty，不产生新桥接器
  会话。**换目标机前必须先在笔记本上结束旧 putty.exe（桥接器）进程**，否则探活测到的还是旧目标机。
- 中继部署的一跳凭据是控制台点击时下发的一次性凭据：**实测 91 秒内可用于二段登录，
  6 分钟后过期**。

## 操作守则（按时间敏感度排序）

1. 用户点击资源后**立即**执行一条 `echo` 探活——这同时完成二段登录（桥接器是懒应答的，
   第一条指令才触发），凭据新鲜度就是会话生死线。
2. `health connected:true` 只代表传输层，shell 是否可用永远以 `echo` 回显为准。
3. 同一目标机反复 `Permission denied` / `中继认证被拒绝（目标主机 X）`：查笔记本 config.json 的
   `relay_hosts[X]` 键与密码（可让用户用原版 putty 手输同一密码做 A/B 验证）；该会话已报废，
   修好后重新点击资源。
4. 二段登录失败/会话报废后不要连环重试命令——命令文本会被密码提示符当密码吃掉，还可能触发锁定。
